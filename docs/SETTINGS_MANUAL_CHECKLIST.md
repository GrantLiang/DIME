# DIMESettings 手動檢查清單

設定視窗（`DIMESettings.exe`）改版或發版前，照這份清單在真實機器上走一遍。自動測試能做的已經自動化，這裡只列自動測試做不到或看不到的部分。

## 自動測試涵蓋了什麼

| 測試 | 涵蓋範圍 |
|------|---------|
| `SettingsScreenshotTest`（5b-13） | 每一頁（四個輸入法的首頁與子頁、載入碼表頁），亮／暗主題 × 96／120／144／192 dpi × 寬／窄版，C++ 與 Rust 視窗的畫面逐像素相同（含子控制項） |
| `SettingsWindowParityTest` | 隨機操作序列後，兩邊的狀態、子控制項屬性、`WM_PAINT` 像素、app 呼叫相同 |
| `SettingsUiaTest` | 每一頁的 UIA 樹相同；下拉選單與編輯框有名稱；每個切換鈕都有可用 UIA Toggle 的勾選框，切換會套用設定 |
| `RichEditViewportTest` | 自建詞庫編輯器的著色、游標、儲存 |

注意：

- 這些測試只證明 **C++ 與 Rust 兩邊一樣**，不證明畫面是對的。版面錯了、文字被截掉、顏色看不清楚，兩邊一樣錯就會通過，所以要人工看截圖（見下方第 1 項）。
- 完整的 C++ 對 Rust 比對要用全 C++ 組合跑（`/p:DimeTestRustEngine=false`）。預設組合下 C++ 視窗的繪圖、子控制項等底層也會呼叫 Rust 的實作，兩邊大部分是同一份程式碼。
- 測試程式沒有 Common Controls v6 manifest，截圖裡的下拉選單、編輯框是傳統樣式。真正的 exe 有 manifest，控制項外觀要人工看。
- 測試不經過 DWM 截圖，而是用各視窗自己的繪圖程式合成畫面。DWM 合成、視窗外框、標題列、陰影都不在比對範圍內。
- 測試視窗沒有被啟用，所以焦點框、游標、滑鼠移上去的效果都沒有比對。

## 準備

- 安裝要測的版本（或用 `DIMESettings.exe` 直接執行建置輸出）。
- 至少一台有兩個不同縮放比例螢幕的電腦，或可以在測試中途改縮放比例。
- 記錄下方表格：日期、版本（`BuildInfo.h` 的版號）、Windows 版本、螢幕縮放。

## 檢查項目

### 1. 截圖檢視

1. 設定環境變數 `DIME_SETTINGS_SCREENSHOT_DIR` 為一個資料夾，執行 `vstest.console.exe src\bin\x64\Debug\DIMETests.dll /Tests:SettingsScreenshotTest`。
2. 打開資料夾裡的截圖（檔名格式：`<主題>_<dpi>_<寬窄>_<頁面>_<C|R>.png`；看 `_R` 即可，`_C` 與它相同）。
3. 每一頁檢查：文字沒有被截掉或重疊、控制項沒有超出卡片、深色主題下文字看得清楚、192 dpi 下圖示與文字比例正常、窄版的漢堡選單與麵包屑位置正確。

### 2. 啟動與單一執行個體

- [ ] 從開始功能表、語言列的設定選項、系統「輸入法選項」都能開啟設定視窗。
- [ ] 視窗已開啟時再從另一個輸入法開啟，會切換到該輸入法的頁面，而不是開第二個視窗。
- [ ] `DIMESettings.exe --legacy` 也開啟新的設定視窗。
- [ ] 關閉後重開，視窗位置與大小恢復；把視窗拖到已拔除的第二螢幕位置後重開，會回到可見範圍。

### 3. 外觀

- [ ] 亮色與暗色主題下，下拉選單、編輯框、捲軸是 Windows 11 的樣式（有 manifest），不是傳統樣式。
- [ ] 視窗開著時在 Windows 設定切換深淺色，視窗立即跟著換色，下拉選單展開的清單也換色。
- [ ] 高對比主題下文字與控制項都看得到。
- [ ] 滑鼠移到側欄項目、卡片、按鈕上有 hover 效果，移開後消失。

### 4. DPI

- [ ] 在 100%、125%、150%、200% 縮放下開啟，文字清楚不模糊。
- [ ] 視窗開著時把它拖到不同縮放的螢幕，版面與字型重新計算，沒有殘影。
- [ ] 視窗開著時改系統縮放比例，同上。

### 5. 版面與導覽

- [ ] 把視窗慢慢拉窄，越過側欄收合寬度時切換成漢堡選單；再拉寬恢復。
- [ ] 窄版時打開漢堡選單、點選項目、點外面關閉，都正常。
- [ ] 每個子頁的麵包屑可以回到上一層。
- [ ] 滾輪在卡片、下拉選單、編輯框上方都能捲動頁面；捲動時控制項跟著移動，沒有殘影。

### 6. 控制項與對話框

- [ ] 每個下拉選單都能展開並選取；選取後設定有存檔（重開視窗後仍是新值）。
- [ ] 切換開關可以用滑鼠點整列切換。
- [ ] 「變更字型」開啟字型對話框，選定後候選字預覽更新。
- [ ] 自訂色彩模式下點色票開啟色彩對話框，選定後預覽更新；「還原預設值」會先詢問。
- [ ] 載入碼表頁的每個「載入」按鈕開啟檔案對話框，載入正確與錯誤的 `.cin` 都有適當訊息。
- [ ] 訊息框在亮／暗主題下顏色正確，Enter／Esc 有效。

### 7. 自建詞庫編輯器

- [ ] 用 DIME 本身在編輯器裡輸入中文，組字與候選字窗位置正常。
- [ ] 貼上一大段文字（上萬行），捲動流暢，看得到的錯誤行有著色。
- [ ] 儲存有錯誤時跳到錯誤行；修正後儲存成功，「儲存」變成不可按。
- [ ] 匯出、匯入的檔案內容正確（UTF-8 與 UTF-16 都試）。

### 8. 鍵盤與無障礙

- [ ] 只用鍵盤（Tab、Shift+Tab、方向鍵、空白、Enter）可以操作所有控制項，焦點框看得到。
- [ ] 朗讀程式（Narrator）唸得出每個下拉選單、編輯框的名稱（列的標題），以及切換鈕的名稱與開關狀態。
- [ ] 用朗讀程式的掃描模式移到切換鈕、按空白鍵可以切換，畫面上的開關跟著改變，重開視窗後仍是新值。
- [ ] 切換鈕現在不在 Tab 順序裡（勾選框不佔畫面，沒有看得見的焦點框），記錄現況即可。

### 9. 設定生效

- [ ] 改候選字字型、色彩、每頁候選字數後，在記事本裡打字，候選字窗反映新設定。
- [ ] 改輸入設定（例如「以空白鍵換頁」）後立即生效，不需重新登入。
- [ ] Store app（例如小算盤的搜尋框）中仍能讀到設定（唯讀）。
